# CaseFlo

## Description

CaseFlo is a web app that a law firm gives to its own clients. It is opened in a phone browser, is not a native app, and has no install prompt or offline mode. It allows law firm clients to check case updates, securely download documents, and pay fees. CaseFlo answers policy questions only from the one plain text policy file the owner uploads.

## Who uses it

* Client: Accesses records with their Android phones and Clients see only their own approved records.

* Staff: Create client accounts and cases, set the assigned staff name and phone, and create updates and invoices. Staff manually generate a 6-digit PIN for the client and email it to them outside the system. Staff cannot approve records.

* Owner: Uploads the policy file and clicks approve on pending records. Staff and Owner authenticate via email and password, and see only their own firm.

## One thing that the agent must do well

Fetch private records by exact customer ID only. Filter policy vectors by firm ID inside the database query before similarity is calculated. Private records are never embedded, indexed, searched by meaning or sent to an AI model.

## Defined Scope for the MVP

* Read only case updates, secure PDF download links, and invoice payments.

* Firm policy Q&A (one question, one answer, no history).

* Overdue account notification banner (invoices >30 days unpaid).

* Staff entry screens (updates, PDFs, invoice amounts).

* Staff screen to create client accounts and generate 6-digit PINs.

* Staff and Owner authentication via email and password.

* Client login via email and Staff-generated PIN, and strict 15-minute lockout after 5 failed attempts.

* Owner approval screens and Owner policy file upload.

* Log only LOGIN with its exact time and DOCUMENT_TAP with the document ID.

## Not in scope items for the MVP

Anything not named in Defined Scope is out of scope. The list below names only likely mistakes:

* In-browser PDF viewers, appointments, and calendars.

* No automated messages of any kind are sent to clients (no SMS, no Termii, no automated system emails).

* No AI agent or scheduled job acts for a client.

* Legal advice (telling a client what to do or what will happen).

* Clients cannot create their own accounts or reset their own PINs.

* Firm subscriptions, tier pricing, and tier limits are not built. A human manages firms.

## Stack

* Next.js with the App Router, and TypeScript in strict mode. Use versions pinned in package.json.

* Prisma and PostgreSQL (pgvector inside the existing DB).

* Flutterwave, in NGN. Amounts are stored as whole numbers in kobo. Convert to Naira for API calls and display only.

* AWS S3. Documents sit in a private bucket. A download link is a presigned URL. The S3 endpoint, region, bucket name, and keys come only from environment variables.

* Gemini API on the free tier. Embeddings use gemini-embedding-001 at 768 dimensions. Answers use gemini-1.5-flash.

* Use `npm` strictly as the package manager and signed cookies for the session method. The test framework, hosting, and CI provider are not chosen; ask before picking.

## Folder map

## How to work in this codebase

* One change means one requested task in one feature, with no unrelated edits.

* Do not add, remove or upgrade any package until the user says yes in the chat.

* Never connect to, query, change or reset a real database with your own tools. A human applies every migration.

* Do not add, rename or remove a model, field or index in schema.prisma without approval.

* Silent means a behavior, limit or text no file states. If this file, the PRD or a rule file disagree, stop and ask.

* End each response with "Assumptions:" listing only choices no file states, or "None".

## Definitions

* Customer ID: The signed-in client's User id. Records reach it through Case.clientId.

* Session: Customer ID, firm ID and role come from the signed-in session only, never from the request.

* Chunk: One piece of the policy file, saved as one PolicyChunk row with its text and vector.

* PIN: A 6-digit code manually generated by Staff. Clients log in with their email and this PIN. All times are stored and compared in UTC.

* Private record: An Update, Document or Invoice row, shown to a client only when approved.

* Overdue: An invoice unpaid for more than 30 days from its createdAt timestamp.

* Approved: The Owner clicked approve.

* Fallback: The screen showing the assigned staff name and phone. If similarity is below 0.75, do not call the LLM and show this screen immediately. If a client has several cases, ask first.

* Presigned URL: A temporary download link made for one tap.
